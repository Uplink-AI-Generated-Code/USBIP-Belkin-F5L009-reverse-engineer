# --- TCP stack (data channel, port 19540) ----------------------------------
# See tcp_connection_and_keepalive.md. Conn state byte at conn+0xd6; two adjacent
# jump tables: in-tick retransmit-fire sub-table @0x37f954 (index = state), and
# tcp_input FSM table @0x37f98c (index = state-4).
#
# RETRACED 2026-10-13 (full fresh trace of the state machine). The earlier claim
# that the ~69s RST is a TCP-layer timer ([conn+0x114] "6000-tick" countdown) is
# REFUTED by the code itself:
#  * The literal 6000 (0x1770) is loaded at exactly ONE site in the whole image
#    (0x318ca8, tcp_arm_open_timer) and is written ONLY to [conn+0x114] as the
#    OPEN/SYN_RCVD watchdog. It is disarmed (=0) at the 7->8 handshake completion
#    (0x319790->0x3197a6), which any clean client ACK of the SYN-ACK reaches
#    (gated: ACK flag set AND [sp+0x2c]!=0 i.e. acks ISS+1). Ours does -> disarmed.
#  * In ESTABLISHED [conn+0x114] is ONLY the retransmit countdown (RTO-scale, not
#    6000). When it expires on an established conn with nothing outstanding
#    (snd.nxt==snd.una) and an open window, the in-tick handler 0x319214 ->
#    0x319222 -> 0x3194b8 just CLEARS [conn+0x114]/[conn+0xfa] and stops. No
#    retransmit, NO RST. So on an idle/fully-acked connection 0x114 self-cancels
#    and cannot cause the wedge. The 0x3193dc RST needs real outstanding data and
#    repeated retransmits -- our zero-retransmit idle captures don't take it.
#  * The other per-tick countdowns also do NOT autonomously RST an idle ESTAB
#    conn: [conn+0x124] keepalive -> probe is a no-op if nothing unacked and never
#    re-arms itself; [conn+0x100] -> job-signal/re-arm (0x31945c/0x319420), no RST;
#    [conn+0x136] -> RST @0x319368 but is NEVER armed nonzero (only cleared in
#    tcp_timer_sched @0x318178) so that path is dead.
# => No TCP per-tick timer fires an autonomous ~69s RST on an established conn.
#    The wedge must be driven from ABOVE (SXUPTP job watchdog tearing the socket
#    via sxuptp_conn_close 0x302a44) or by an incoming-segment path. Next: trace
#    the SXUPTP job FSM lease/idle timeout (job[4], [conn+0xe4], [conn+0x16] via
#    0x3159d0 job-event post, sxuptp_conn_state_machine @0x302fb0).
